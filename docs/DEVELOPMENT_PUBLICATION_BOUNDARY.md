# 개발 프로젝트와 출판 프로젝트의 분리 원칙

## 저장소 역할

| 구분     | 실제 개발 프로젝트              | 공개 출판·실습 프로젝트            |
| -------- | ------------------------------- | ---------------------------------- |
| 목적     | 조직의 제품·운영 요구 충족      | 독자의 학습과 재현                 |
| 데이터   | 승인된 내부 데이터·설정         | 합성 데이터만                      |
| 알고리즘 | 조직 고유 구현 가능             | 최소·일반화된 교육 패턴            |
| 평가     | 내부 회귀·비공개 공격 세트 가능 | 공개 수용 기준과 공개 테스트       |
| 식별자   | 내부에서만 사용                 | 내부 이름·URL·SHA·경로 금지        |
| 배포     | 조직 인프라 정책                | 로컬 실행이 기본, 외부 연동은 선택 |

## 단방향 전달 규칙

실제 개발 프로젝트에서 공개 프로젝트로 파일을 복사하지 않습니다. 개념을 공개할 필요가 있으면 다음 순서로 다시 작성합니다.

1. 해결하려는 일반 문제를 한 문장으로 추출한다.
2. 회사·제품·고객 식별자를 제거한다.
3. 내부 알고리즘 대신 교과서 수준의 최소 패턴으로 새로 구현한다.
4. 합성 입력과 공개 수용 기준을 새로 만든다.
5. 원본 경로를 모르는 검토자가 독립 저작·재현 가능성을 확인한다.

공개 자료에서 발견한 개선점은 실제 개발 프로젝트에 적용할 수 있지만, 반대 방향의 복사는 허용하지 않습니다.

## 출판 전 차단 조건

- 내부 저장소·조직 계정·branch·commit·path가 한 건이라도 남아 있음
- 실제 prompt·평가 rubric·운영 threshold가 포함됨
- 고객·개인정보 또는 실제 secret 형식의 fixture가 포함됨
- 공개 코드의 독립 작성 근거와 제3자 라이선스가 설명되지 않음
- 공동저자 표시와 기여 범위가 누락됨
