# 강사용 운영 가이드

## 진행 원칙

정답 코드를 먼저 설명하지 않습니다. 실패 사례를 재현하고, 역할별 계약과 증거가 왜 필요한지 학습자가 말하게 한 뒤 최소 구현으로 이동합니다.

## 권장 시간

| 주차  | 개념 | 실습  | 검증·회고 |
| ----- | ---- | ----- | --------- |
| 1주차 | 45분 | 120분 | 75분      |
| 2주차 | 60분 | 120분 | 60분      |
| 3주차 | 60분 | 135분 | 45분      |

## 개입 지점

- 학습자가 모델 답변을 Evidence로 착각하면 독립 테스트와 diff를 요구합니다.
- Worker 역할이 겹치면 구현보다 ownership map을 먼저 수정합니다.
- Reviewer가 파일을 고치려 하면 finding만 남기고 Worker에게 돌려보냅니다.
- 같은 실패가 반복되면 prompt를 늘리지 말고 중단 조건과 TaskSpec을 점검합니다.
- 외부 DB·배포 설정이 수업을 막으면 선택 부록을 건너뛰고 핵심 로컬 실습을 마칩니다.

## 채점

완성 기능 수보다 경계, 재현성, 실패 종료, 독립 검증, 인계 품질을 우선합니다. `docs/LAB_ACCEPTANCE_CRITERIA.md`와 주차별 test 이름을 채점 기준으로 사용합니다.
