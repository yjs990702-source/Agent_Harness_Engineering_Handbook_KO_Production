# PR Draft Skill

## 목적

검증된 변경 내용을 사람이 검토할 수 있는 PR 본문 초안으로 정리합니다. 이 Skill은 파일을 수정하거나 GitHub API를 호출하거나 PR을 게시하지 않습니다.

## 입력 계약

- 문제와 변경 이유
- 변경한 공개 교육 파일의 범위
- 수용 기준 ID와 대응 Evidence
- 실행한 로컬 검증 명령과 결과
- 알려진 위험과 rollback 방법

입력 중 하나라도 없으면 추측하지 말고 `확인 필요`로 표시합니다. Secret, 실제 고객 데이터, 회사 내부 경로, 출판 원고 내용은 입력과 출력에 포함하지 않습니다.

## 절차

1. 변경 파일이 교육 코드·테스트·강의 문서 범위인지 확인합니다.
2. 수용 기준마다 재현 가능한 Evidence reference가 있는지 확인합니다.
3. 검증 명령을 실제 실행한 명령과 아직 실행하지 않은 명령으로 구분합니다.
4. 부작용, 호환성, 보안, 미검증 외부 서비스 위험을 기록합니다.
5. 아래 출력 계약으로 PR 본문 초안을 반환하고 게시 전 사람 검토를 요청합니다.

## 출력 계약

```markdown
## 문제와 변경 이유

## 변경 범위

## 수용 기준과 Evidence

## 로컬 검증

## 위험과 제한

## Rollback
```

완료, 통과, 안전이라는 표현은 대응하는 테스트·diff·review reference가 있을 때만 사용합니다.

## 금지 행동

- Git commit, push, PR 생성 또는 외부 쓰기
- 검증하지 않은 결과를 통과로 표현
- Secret, 운영 URL, 개인정보, 내부 코드나 원고 복사
- 수용 기준을 맞추기 위한 테스트 skip 또는 assertion 약화
